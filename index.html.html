KT × 포시에스 기술 논의 정리

KT Paperless 사업 종료에 따른 이폼사인 이관, KT 공전소(공동전자문서보관소) 연계, KT 전용 화이트라벨 채널 구축을 주제로 진행된 연구소·클라우드사업본부 초도 기술 미팅 내용을 안건별로 정리했습니다.

이관 대상 고객/문서의 범위는 어떻게 정의하는가?
답변 확인

  • Open API 이용 고객 중 이관 희망 6개사, 이 중 도입 의사가 확고한 곳은 KT Estate 1곳(무선 MGT들이 사용하는 중계기 설치 계약서 용도로 활용, 타부서에서 이폼사인 이용 중)
2
현재 공전소에 보관 중인 문서의 저장 구조(포맷·메타데이터·원본/서명 검증정보 포함 여부)는?
부분 답변
서식 개수 890건 / 총량 1.8GB / 기타 첨부파일 없음. 단, 1건당 용량은 별도 파악이 어려운 상태.
  • 연구소 확인 필요 사항: 890건이 단순 PDF(작성 완료 문서)인지, 데이터가 포함된 템플릿인지
  • KT 측 답변: 추가 파악 후 전달 예정 / 사업용 계정처럼 접근 가능하도록 허용 가능
3
데이터 이관은 API 방식인지 배치(파일) 방식인지, 제공 가능한 인터페이스 명세가 있는가?
부분 답변
Open API는 이폼사인과 별도로 운영되는 구조라, 이관 시 고객사 측 일부 소스코드 수정이 필요하다는 점만 확인됨. 구체적 인터페이스 명세는 미확정.

부가 논의질문 리스트 밖에서 오간 내용

  • 신규 유입(홈페이지를 통한 개인 회원가입)은 있으나, 고객센터를 통한 청약 신규 유입은 거의 없음
  • 기존 고객 단가 협의: KT는 "추가 혜택을 제공해 최대한 많은 고객이 이관하도록" 해달라고 요청
  • 문서 작성 이력 등 기타 정보까지 이관 시 비용이 추가 발생 → 포시에스 측에서도 심도 있게 검토 필요
  • 이용 정책 수립 필요 (예: 이관 후 문서 조회만 가능 등) + 추가 비용 발생 여부에 대한 고객 고지 필요

  • 전자계약 시스템 자체 보관은 3개월, 이후 공전소 key값을 포시에스로 넘겨받아 연계하면 공전소 상 최대 100년까지 보관 가능하다는 보충 설명이 있었음

C
KT 전용 회원가입 URL / 화이트라벨
질문 7개 · 답변 5 · 미논의 2
1
KT 브랜드 적용 범위는 가입 화면에 국한되는지, 서비스 UI 전반까지 포함하는지?
답변 확인
서비스 UI는 기존 이폼사인 UI로 유지하는 방향으로 조율 필요 - 서비스 자체는 이폼사인으로서 관리하고 싶다는 것이 포시에스 측 기본 입장.
2
가입 시 KT 시스템(고객 DB, 인증 체계 등)과의 실시간 연계가 필요한가, 단순 채널 코드 태깅으로 충분한가?
답변 확인
Third Party로 별도 관리하는 방안 논의됨: 회원가입은 API로 지원하고, RSA 방식으로 KT 회원가입을 통해 고객이 유입되며 이폼사인 자체 회원가입은 불필요.
  • 참고 사례: 자동차리스계약 플랫폼이 유사한 방식으로 운영 중
3
가입 이후 고객 CS·정산·해지 처리의 운영 주체는 KT인지 FORCS인지?
답변 확인
KT는 청약을 KT 쪽에서 잡고 넘기는 방식을 희망 (플랫폼서비스팀 매출로 잡히기 때문).
  • 통신 요금 대부분이 후불제이므로 문서 정산도 후불 방식으로 진행 필요
  • 정산 주기(분기별/반기별 등)는 포시에스가 제안 가능
4
KT 채널 가입 고객에 대한 요금제는 별도 정책으로 운영되는가, 기존 이폼사인 요금 체계를 따르는가?
답변 확인
KT 기본 가격정책이 이폼사인 충전형 요금제의 2배가량 되기 때문에, 건당 700원의 KT 채널 유입 고객 한정 특가로 제공 가능
5
이관 고객은 어떻게 취급하면 될지?
방향만 확인
개별 계약 진행 시 협상 단가로 진행 가능하며, 이관·가격정책 프로세스가 정립된 이후에 고객 대상 사업종료 고지가 가능.
6
SSO 적용을 원한다면 KT 측 IdP(인증 서버) 연동 규격은 무엇인가?
미논의
이번 미팅에서 논의되지 않음
7
채널 코드별 트래킹 데이터(가입 전환율 등)를 KT가 별도로 요구하는 리포팅 스펙이 있는가?
미논의
이번 미팅에서 논의되지 않음

부가 논의질문 리스트 밖에서 새로 나온 트랙

  • KT 비즈메카 EZ: ERP 등 다양한 기능을 탑재한 서비스 제공 사업 진행 중. RS구조·SaaS 연동 활용 가능하며, 담당 부서에서도 포시에스와의 협약을 희망
  • (별개 제안) 디바이스 판매 수수료를 포시에스에 제공하고, 고객 소개도 가능한지 → KT-포시에스 MOU로 사업 스케일이 확대될 수 있다는 기대 언급

종합 코멘트

A(문서 마이그레이션)는 이관 범위·API 방식 위주로만 답변되어 식별자 체계, 원본성 유지, 폐기 정책 등 실무 세부사항이 비어 있습니다. B(공전소 연계)는 기술 규격 질문 7개 중 사실상 1개만 부분 답변되어 세 안건 중 공백이 가장 큽니다. C(화이트라벨)는 정산·운영주체 방향은 어느 정도 확인됐지만, SSO·요금제·리포팅 스펙은 전혀 논의되지 않았습니다. 다음 미팅에서는 B와 C의 미답변 기술·정책 질문을 우선순위로 다시 제기하는 것이 필요해 보입니다.
